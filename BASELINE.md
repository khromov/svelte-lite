# Svelte runtime baseline (Phase 1, historical): Hello World with Bun.build

Svelte 5.57.1 (local monorepo source at `../svelte/packages/svelte`: commit `f90853565966`, i.e. upstream `main` 10 commits after the `svelte@5.57.1` tag), Bun 1.4.2, macOS arm64. Built 2026-09-27. The project now builds from a vendored official checkout instead (see "How to run").

> **Phase 2 update.** The numbers in this document are the **historical, `mount()`-based** Hello World reference from Phase 1. The project has since moved on:
>
> - Every test app is now SSR-rendered and **hydrated** (`hydrate(App, { target })`).
> - The throwaway `exp-*` variants were replaced by `optimized` (lossless build fixes) and `minimal` (svelte-lite feature drops); see **COMPARISON.md** and **PATCHES.md**.
>
> The hydrate-based vanilla Hello World is 41,544 B min / 15,542 gzip / 13,977 brotli. That is within 20 B of the mount-based 41,527, because vanilla already bundled `hydrate()` via custom elements.
>
> The Phase 1 techniques live on in `patches/optimized.ts` and `patches/minimal.ts`:
>
> | Phase 1 experiment | now                                    |
> | ------------------ | -------------------------------------- |
> | `exp-dev-const`    | `DEV_CONST`                            |
> | `exp-barrel`       | `NAMED_IMPORTS`                        |
> | `exp-pure`         | `PURE` + `DISCLOSE`                    |
> | `exp-mode-flags`   | the `constImports` of `LEGACY`/`ASYNC` |
> | private-member DCE | `postpass.ts`                          |
> | `exp-no-hydration` | dropped: hydration is required         |
> | `exp-drop-console` | rejected                               |
>
> The analysis below (why code survives Bun's tree-shaking, and Bun's limitations) still holds, with one addition found in Phase 2: a local `const` inside a _function_ is also only folded if it is the first statement of that function body.

## TL;DR (Phase 1, mount-based)

| `main.min.js`                                             |           raw |          gzip |       brotli |
| --------------------------------------------------------- | ------------: | ------------: | -----------: |
| **baseline** (vanilla Svelte, standard Bun DCE options)   |    **41,527** |    **15,531** |   **13,984** |
| all cheap build-time techniques stacked (`exp-all`)       | 26,035 (−37%) | 10,062 (−35%) | 9,121 (−35%) |
| `exp-all` + dead private class member removal (post-pass) | 24,005 (−42%) |  9,428 (−39%) | 8,524 (−39%) |

- For this app the compiler folds `$state('world')` into a static string. The component only calls `from_html` and `append`, and everything else is runtime overhead. **Only 22% of the minified bytes execute** while mounting Hello World.
- **The largest leak is a Bun limitation, not Svelte:** every `if (DEV)` branch ships. esm-env resolves correctly to `false.js`, but Bun 1.4.2 never propagates `export default false` across modules, and it only folds a local `const` in narrow cases. That leak is 8.3 KB min / 2.7 KB gzip.
- The second largest is `custom-element.js`. Its top-level side effect (`if (typeof HTMLElement === 'function') SvelteElement = class …`) keeps the Svelte-4 `legacy-client.js`, `hydrate()`, `flushSync()` and more in the bundle: 5.3 KB min / 1.8 KB gzip. Svelte has no `"sideEffects"` field, and the compiler's `import * as $` defeats barrel optimisation.
- Bun's `define` doesn't work for any of Svelte's mode flags. They are module-level `let`s (`hydrating`, `legacy_mode_flag`, `async_mode_flag`) or imported constants (`DEV`). A small source-rewrite plugin (`plugins/patch.ts`) works around this. It never modifies the Svelte repo.

## How to run (current)

```sh
bun install                              # happy-dom + types (postinstall re-links node_modules/svelte if a Svelte is vendored)
bun run vendor 5.57.1                    # official Svelte (tag svelte@5.57.1) -> vendor/svelte/5.57.1/ + pnpm install; selects it in svelte-ref.json
bun run build.ts                         # baseline, every app in apps/ -> dist/baseline/<app>/
bun run build.ts minimal --app=reactive  # one variant/app
bun run build.ts --all                   # every variant x app (check + measure + coverage each)
bun run check.ts                         # behavioural checks for everything in dist/ + patch anchors + negative tests
bun run test:svelte minimal              # Svelte's own test suite vs unpatched Svelte (see SVELTE_TESTS.md)
bun run measure.ts --compare baseline optimized minimal
bun scripts/comparison.ts                # regenerate COMPARISON.md tables
bun scripts/patches-doc.ts               # regenerate PATCHES.md tables (and verify every patch anchor)
bun scripts/coverage.ts minimal reactive # which shipped functions actually ran
bun run serve.ts                         # static server: open /dist/<variant>/<app>/index.html
bun run check.ts --anchors               # only verify every patch anchor against the selected Svelte (no build)
```

**Choosing the Svelte version.** The build always uses the _official_ Svelte source, vendored by `scripts/vendor-svelte.ts`, plus the documented patches. The source is never edited.

- `bun run vendor <ref>` makes a shallow clone of `https://github.com/sveltejs/svelte.git` (or `--repo=<url|path>`) into `vendor/svelte/<ref>/` and runs `pnpm install --frozen-lockfile` with the checkout's own lockfile. It then records the selection in `svelte-ref.json` (`{ repo, ref, tag, sha, version, path }`).
  - Refs: `main`, `5.57.1` (resolved to the tag `svelte@5.57.1`), `svelte@5.57.1`, a full commit sha, or any other branch or tag.
  - Several refs live side by side, so switching back to an already-vendored ref takes about a second.
  - Options: `--update` fetches the latest `main`; `--no-activate` only fetches; `bun run vendor --list` shows what is vendored.
  - `bun run vendor` with no ref re-creates exactly the commit pinned in `svelte-ref.json`, like `npm ci`.
- **Per-command override:** `--svelte=<ref>` on `build.ts`, `check.ts` and the scripts, or `SVELTE_REF=<ref>`. `SVELTE_DIR=/path/to/svelte/packages/svelte` still points at any checkout, e.g. `../svelte`.
  - An override re-points the shared `node_modules/svelte` symlink. Don't run two builds with different refs at the same time.
- **Guard:** the build fails if the checkout's `packages/svelte` has uncommitted changes, or if its HEAD is not the pinned sha. `SVELTE_ALLOW_DIRTY=1` turns the first into a warning, and reports are then stamped as dirty.
- **Provenance:** every `report.json` records `svelte: { repo, ref, tag, sha, version }`. The build prints the same, and the generated sections of COMPARISON.md and PATCHES.md start with it.
- `build.ts --out=<dir>` (and `check.ts --out=<dir>`) writes to or reads from `<dir>/<variant>/<app>/` instead of `dist/`.

Set `SVELTE_LITE_DUMP=/dir` to write every patched Svelte module to disk for inspection.

| `scripts/link-svelte.ts`                          | The single source of truth for which Svelte is used (`SVELTE_DIR`, `SVELTE_REPO`, `SVELTE_INFO`), the uncommitted-changes guard, and the `node_modules/svelte` symlink (see below)                                              |

**Referencing the vendored Svelte.** `node_modules/svelte` is a plain symlink to the selected checkout's `packages/svelte`. It is re-pointed atomically whenever the selection changes, and re-checked by every build. `"svelte": "file:…"` was rejected because `bun install` then installs all of Svelte's (dev)dependencies into this project. `link:` needs global `bun link` registration. Bun follows the symlink to the real path, so `svelte`, `svelte/internal/client`, `svelte/internal/disclose-version`, `svelte/internal/flags/*` resolve through Svelte's own `exports`, `#client/constants` through its `imports`, and `esm-env`/`clsx`/`acorn` come from the monorepo's `node_modules`.

**Resolution verified** (metafile, enforced by `verifyResolution()` in `build.ts` on every build):
`svelte` → `src/index-client.js`, `esm-env/development` → `false.js` (DEV = false), `esm-env/browser` → `true.js`, `esm-env/node` → `false.js`, `#client/constants` → `src/internal/client/constants.js`.

## Bun.build options

| option                             | value                                                                               | why                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `target`                           | `'browser'`                                                                         | Browser resolution, `browser` condition                                                                                                                                                                                                                                                                                                             |
| `format`                           | `'esm'`                                                                             | Flat, scope-hoisted output, no wrapper                                                                                                                                                                                                                                                                                                              |
| `conditions`                       | `['browser','production']`                                                          | `production` is **required**: without it `esm-env/development` falls to `dev-fallback.js`, a _runtime_ `globalThis.process?.env?.NODE_ENV` check that `define` can't reach (+355 B)                                                                                                                                                                 |
| `define`                           | `process.env.NODE_ENV: "production"`, `import.meta.env.{DEV,PROD,SSR,MODE}`         | **Important:** Bun 1.4.2 implicitly adds the `development` condition unless NODE_ENV is defined as production here or set in the build process env. With `development` active, esm-env's DEV is `true.js` and you ship a dev build _even with `conditions: ['production']`_. See findings.                                                          |
| `minify`                           | min: `{whitespace, syntax, identifiers}`; unmin: `false`; readable: `{syntax}` only | Constant folding, `if(false)` removal and known-pure-constructor detection live in `minify.syntax`. `keepNames: false`.                                                                                                                                                                                                                             |
| `treeShaking`                      | `true`                                                                              | Default, explicit                                                                                                                                                                                                                                                                                                                                   |
| `ignoreDCEAnnotations`             | `false`                                                                             | Respect `/*@__PURE__*/` and `sideEffects`. Svelte has no `sideEffects` field, so nothing gains from it.                                                                                                                                                                                                                                             |
| `drop`                             | `['debugger']`                                                                      | `console` is **not** dropped in the baseline. Production Svelte still reports warnings as `console.warn('https://svelte.dev/e/<code>')`, and `hydrate()` logs failures. `drop` also deletes call arguments even when they have side effects. Measured in `exp-drop-console`: −1.9 KB alone, but only −113 B once DEV code is gone, so not worth it. |
| `env`                              | `'disable'`                                                                         | Never inline the build machine's `process.env`                                                                                                                                                                                                                                                                                                      |
| `features`                         | `[]`                                                                                | `bun:bundle` `feature()` flags exist in 1.4.2, but stock Svelte doesn't use them, and `feature()` is only accepted directly in an `if`/ternary condition (see findings)                                                                                                                                                                             |
| `optimizeImports`                  | `[]` (variants: `['svelte']`)                                                       | Barrel optimisation; see `exp-barrel`                                                                                                                                                                                                                                                                                                               |
| `splitting`                        | `false`                                                                             | One entry                                                                                                                                                                                                                                                                                                                                           |
| `packages`                         | `'bundle'`                                                                          | Svelte must be bundled                                                                                                                                                                                                                                                                                                                              |
| `deprecatedNamespaceObjectSetters` | `false`                                                                             | Getter-only namespace objects (future default). No size effect here.                                                                                                                                                                                                                                                                                |
| `sourcemap`                        | `'none'`                                                                            | Keeps measured files free of map comments                                                                                                                                                                                                                                                                                                           |
| `metafile`                         | `{ json, markdown }`                                                                | `meta.<mode>.json` feeds `measure.ts`, and `meta.<mode>.md` is Bun's LLM-friendly report. Bun has no `--analyze`, so the metafile replaces it.                                                                                                                                                                                                      |
| `throw`                            | `false`                                                                             | Errors are printed via `result.logs`                                                                                                                                                                                                                                                                                                                |

Not available in Bun 1.4.2 (per the esbuild migration table): `pure` (esbuild `--pure:fn`), `inject`, `mangleProps`, `alias` (use plugins), `--analyze`, `sideEffects` in `onResolve` results.

`main.js` is _not_ the same code as `main.min.js`. Without `minify.syntax`, Bun folds no constants, removes no `if (false)` branches, and doesn't recognise `new WeakMap`/`new Set` as pure. So `main.js` also carries e.g. `bindings/size.js`'s unused `ResizeObserverSingleton` class and `timing.js`. **Read `main.readable.js` for analysis.** Its top-level statements align 1:1 with `main.min.js`, which is how `measure.ts` attributes minified bytes to named functions.

## Bun 1.4.2 findings / limitations

1. **Implicit `development` condition.** `Bun.build` resolves the `development` export condition unless `define['process.env.NODE_ENV']` is `"production"` or `NODE_ENV=production` is set in the build process environment. Setting `process.env.NODE_ENV` inside the build script is too late. It overrides an explicit `conditions: ['production']`. Without `production`, esm-env falls back to `dev-fallback.js`. Neither behaviour is documented. `build.ts` now fails the build if esm-env resolves wrong.
2. **No cross-module constant propagation.** `export const X = false` / `export default false` stay as variables in importers (`if (false_default)`), even with `minify.syntax`. This is the root cause of the 8.3 KB DEV leak.
3. **Local `const` folding only works for a module's leading statements.** A top-level `const` is folded only if it comes before the first `import` or any other statement. Any **named re-export** (`export { x } from '…'`) anywhere in the module also defeats it, because Bun hoists it as an import. `export *` doesn't. `let` is never folded. Workaround in `plugins/patch.ts`: prepend the consts and split re-exports into `import` + `export`.
4. **Class members are never tree-shaken**, including unreferenced `#private` methods (safe to remove). They cost 2 KB in `exp-all` (finding #5).
5. **Unused nested function declarations/arrow consts are not removed**, e.g. `proxy()`'s `update_path`.
6. **`Symbol('x')`, array/string spreads and global property reads count as side effects.** Bun does auto-mark `new Set/Map/WeakMap` as pure, but only with `minify.syntax`. Calls to empty functions are kept.
7. **`feature()` from `bun:bundle`** works (`features: [...]`), but only _directly_ in an `if` condition (including `&&`/`!` inside it) or a ternary test. `const DEV = feature('X')` and `feature('X') && y` in expression position are build errors. It can't replace `DEV` without rewriting every use site, so `constImports` is the more robust choice.
8. **`sideEffects` can't be injected.** `onResolve` doesn't support the `sideEffects` result, `Bun.build({ files })` overrides don't apply to `package.json`, and esbuild-style `pure` isn't supported. `optimizeImports` is the only lever for barrels, and only with named imports.
9. **`metafile: { json, markdown }`** works in the JS API, but the paths resolve **relative to `outdir`** (the docs' example `./dist/meta.json` with `outdir: './dist'` would land in `dist/dist/`), and `BuildConfig.metafile` is typed as `boolean` only.
10. **`minify: false` is not "same code, unminified".** Tree shaking still runs, but constant folding, branch removal and pure-constructor detection don't. Hence the extra `main.readable.js` build.
11. **`bun test --coverage` (lcov) is unusable at function granularity for bundles.** Functions that never ran get non-zero counts on their last body line. `scripts/coverage.ts` uses explicit probes instead.
12. **(Phase 2) The const-prefix rule also applies inside functions.** `const defer = false;` is folded only when it is the first statement of its function body. After a `var` it becomes `let defer = !1` and nothing folds. The `minimal` patches insert such consts at the top of the function.
